# 正式模型訓練前完整驗收清單

這份清單的目的不是保證獲利，而是避免用錯資料、錯帳務或錯執行假設訓練出看似漂亮、
實際不可部署的模型。正式訓練只在所有「訓練前」門檻通過後開始。

## 現在已具備

| 區域 | 已完成的保護 |
|---|---|
| 市場 | BTC/USDT Binance USD-M 永續，研究與下單市場一致 |
| 資料 | 已收盤 K 線、多週期因果對齊、缺 K／過期／異常價格與 Spread 守門 |
| 特徵 | Train-only scaler、特徵契約、Transformer／FinBERT 可用性檢查 |
| 交易 | SAC 多空目標曝險、下一根開盤成交、費用、滑價、Spread、Funding、強平 |
| 自適應 | Regime、信心、波動、中度 Drift 連續降倉、嚴重 Drift 禁止加風險 |
| 風控 | 每筆風險、單日損失、連敗、軟硬回撤、逐步縮倉、倉位與槓桿硬上限 |
| 資金 | 入出金獨立帳本與資金流修正回撤，入金不算獲利、出金不算虧損 |
| 執行 | Client Order ID 去重、ReduceOnly、逐倉、交易所停損停利、持倉對帳 |
| 營運 | Emergency Halt、稽核雜湊鏈、PostgreSQL、事件重播、故障注入與監控 |
| 研究 | 時序切分、樣本外評估、Walk-forward、多 Seed、模型 Registry 與回滾框架 |

## 訓練前必須通過

| 項目 | Go 條件 | 不通過的後果 |
|---|---|---|
| 資料契約 | 無缺欄、NaN、Inf、重複時間、非法 OHLC | 直接阻擋訓練 |
| 時序切分 | Train、Validation、Test 完全不重疊 | 避免資料洩漏 |
| 特徵因果性 | Feature 不得含 target、future、next price | 避免偷看答案 |
| 市場一致 | BTC/USDT、Binance Futures、Perpetual 帳務 | 避免研究與下單錯位 |
| 成本 | Fee、Spread、Slippage 均為非零保守值 | 避免虛假獲利 |
| 多空 | 永續環境啟用 short，空頭上限獨立設定 | 避免模型只學多頭 |
| 資料量 | 正式起點至少 50,000 根、跨度至少 730 天 | 不足只能 smoke |
| 市場狀態 | 牛、熊、盤整、高低波動與重大事件期間都有覆蓋 | 避免單一行情記憶 |
| 合約資料 | Funding、OI、Spread 等欄位有可量化覆蓋率 | 缺資料須做 ablation |
| Transformer | 歷史推論覆蓋至少 50%，不可用時 fail closed | 禁止全零假特徵 |
| FinBERT | 新聞必須保留發布時間、取得時間與來源，不得回填未來新聞 | 避免新聞洩漏 |
| 風控 | 研究階段槓桿不高於 3x、每筆風險不高於 1%、硬回撤不高於 15% | 超過顯示警告 |
| 可重現 | Dataset、設定、程式版本、Seed、套件與成品雜湊均可追查 | 無法比較實驗 |

檢查命令：

```powershell
cd D:\AIQuantTradingSystem
python scripts\check_pretraining_readiness.py `
  data\processed\rl\environments\你的環境資料夾
```

回傳碼 `0` 才適合正式訓練；`1` 代表只有警告，`2` 代表資料完整性錯誤。Smoke 測試可加
`--allow-smoke`，但正式訓練不可使用這個參數。每次 `train_rl_agent` 也會自動執行同一套
硬性檢查，並把報告寫入該次 `training.json`。

## 訓練後才能驗證

下列項目無法在「尚未訓練」時完成，不能用程式碼存在代替實際證據：

1. Transformer 校準、方向正確率、MAE 與不同 Regime 的穩定性。
2. SAC 至少 5 個 Seed、Walk-forward、最終封存 Holdout 與成本壓力測試。
3. 無 Transformer、無 FinBERT、無合約特徵的 Ablation，比較新增特徵是否真的有價值。
4. Profit Factor、Expectancy、Calmar、最大回撤、換手與零強平門檻。
5. 連續 3 至 6 個月 Paper／Testnet；至少經歷斷線、延遲與高波動事件。

## 實盤前仍需外部條件

- Binance Testnet API Key、帳戶 One-way／ISOLATED／槓桿與權限核對。
- User Data Stream 必須成為訂單和持倉的主要狀態來源，REST 只負責補帳與對帳。
- WebSocket 24 小時重連、listen key 更新、sequence gap 與斷線重播長時間驗收。
- 入出金要用交易所 transfer reference 寫入 `capital_flows.csv`，不可只改初始本金。
- 備份還原、告警送達、主機斷電、網路中斷與交易所 timeout 的實機演練。
- 稅務、交易所地區限制、API 使用條款與真實資金責任由帳戶持有人確認。

## 人與數學的邊界

數學可以在人工上限內調整 Regime、Drift、波動、信心、部位和允許槓桿；最大槓桿、最大
回撤、單日損失、每筆風險、允許標的與 Live 開關必須保持人工硬限制。模型永遠不能自行
提高這些上限，也不能在實盤隨機探索。
