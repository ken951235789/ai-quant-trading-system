# 交易決策治理與驗收

## 每根 15m K 線的固定順序

1. Data Guard 檢查五週期資料完整、連續、已收盤、未過期且 Spread 合理。
2. FinBERT 依發布時間附加情緒、信心、新聞數量與可用旗標。
3. Transformer 輸出未來報酬、波動、方向機率與不確定性。
4. SAC 同時讀取市場、FinBERT、Transformer 與帳戶狀態，提出連續目標曝險。
5. Regime Detector 分類多頭、空頭、震盪、不確定或高波動市場。
6. Capital Manager 依方向信心、波動、Regime 與回撤縮放新增風險。
7. Risk Governor 套用持倉、停損、回撤與最短持有等硬限制。
8. Portfolio Risk 限制整體、方向、策略、單一標的與日／週／月虧損。
9. Paper／Live Execution 使用唯一決策識別碼，避免重複下單並核對成交。
10. 帳務、模型監控、稽核鏈、Watchdog 與通知保存結果並監督常駐服務。

任何一層拒絕新增風險時，減倉和平倉仍優先放行。資料無效、模型輸入缺欄或本機持倉
大於交易所實際餘額時會 fail closed，不會用上一個訊號繼續開倉。

## 20 根 K 線驗收

```powershell
cd D:\AIQuantTradingSystem
python scripts\verify_trading_pipeline.py `
  --model-dir data\processed\rl\environments\你的環境\training\你的SAC訓練 `
  --bars 20 `
  --end-at "2026-08-01T20:00:00Z" `
  --output-root data\research\role_validation
```

`roles` 會逐項列出資料、FinBERT、Transformer、SAC、Regime、資金、模型監控、固定風控、
投資組合、執行、帳務與冪等證據；摘要也會保存為 `verification_summary.json`。
`status=passed` 代表這些工程角色可執行；它不代表
模型已有獲利能力。還必須另外確認 `model_quality_eligible=true`，並完成多 Seed、
Walk-forward、保留測試集、成本壓力測試與長期 Testnet。

## 稽核欄位

`data/paper_trading/<帳戶>/predictions.csv` 會保存：

- SAC 原始目標、Transformer／資金調整後目標、門檻後目標與最終核准目標。
- FinBERT 情緒、信心與該根 K 線是否有可用新聞。
- Transformer 牛熊機率、波動、不確定性與市場 Regime。
- 信心、波動、Regime、單帳戶風控使用的倍率。
- 模型輸入漂移、投資組合曝險、是否停機與完整拒絕原因。

Futures Gateway 已支援 Testnet 與受控 Live 多空交易。正式 Live 還必須使用通過多 Seed、
Walk-forward、Paper 證據並升級成 Registry Champion 的模型；資料、私有事件流、交易所
對帳或磁碟異常都會 fail closed。程式完成不等於模型具有可持續獲利能力。
